# 출결메이트 (Chulgyeol-Mate)

대한민국 중등학교 담임교사의 **나이스(NEIS) 일일출결 입력 부담**을 줄이기 위한 보조 웹앱 + 브라우저 자동화 도구입니다.

> 이 프로젝트는 교육부·KERIS 공식 프로그램이 **아닙니다**.  
> 나이스 화면의 최종 저장·확인 책임은 항상 담당 교사에게 있습니다.  
> 학생 개인정보는 외부 서버로 전송하지 않는 것을 1원칙으로 합니다.

---

## 1. 해결하려는 문제

4세대 나이스의 `[학급담임] - [출결관리] - [일일출결관리(담임용)]` 화면은 다음 이유로 입력이 느리고 실수가 많습니다.

- 조회 → 날짜 이동 → 학생·교시 셀 클릭 → 출결유형 선택 → 사유 입력 → 저장을 **매일·학생별로 반복**
- 결석 / 지각 / 조퇴 / 결과 / 출석인정 / 기타결석 구분이 많고, **기타결석은 사유 필수**
- 조회·종례·교시별 입력이 따로 존재
- 주말·공휴일·수업일수가 아닌 날에 잘못 입력하면 중단·오류 발생
- 전입·편입·중도입학 학생은 개근·특기사항 처리 규칙이 다름
- 학부모 온라인 결석신고·체험학습 신청과 담임 화면을 대조해야 함
- 월말 마감, 출결 특기사항, 개근 일괄입력은 별도 점검이 필요

현장에서는 엑셀 출석부 → 나이스 복사·붙여넣기, 또는 크롬 확장 프로그램(내모 NAEMO 등)으로 우회하고 있습니다.  
출결메이트는 이 흐름을 **교사 친화 UI(웹앱) + 나이스 화면 자동입력(매크로/확장)** 으로 묶습니다.

---

## 2. 제품 원칙

1. **로컬 우선**: 명단·출결·사유는 브라우저/기기 안에서만 처리. 클라우드 동기화는 기본 비활성.
2. **미리보기 후 전송**: 자동입력 전 “무엇이 바뀔지”를 교사에게 보여 주고 확인받는다.
3. **중복 입력 방지**: 이미 반영된 건은 다시 넣지 않는다.
4. **규칙 검증**: 주말·공휴일, 사유 공란, 교시 누락, 출석인정 유형 불일치를 입력 전에 막는다.
5. **공식 시스템 존중**: 나이스 로그인·인증서·권한은 교사가 직접 수행. 우리는 UI 보조만 한다.
6. **투명성**: 자동입력이 어떤 셀을 어떤 값으로 바꾸는지 로그를 남긴다(학생 식별정보는 로컬만).

## 3. 권장 구조

```
출결메이트
├── web/                 # 교사 출결 정리 웹앱 (PWA 가능)
│   ├── 학급 명단 가져오기 (엑셀/CSV, 학년·반·번호·이름)
│   ├── 일일·기간 출결 입력 UI
│   ├── 사유 템플릿 / 출석인정 유형
│   ├── 검증 엔진 (휴일, 필수사유, 교시 규칙)
│   └── 전송 대기열 + 미리보기
├── extension/           # 크롬 확장 (또는 userscript)
│   └── 나이스 일일출결관리(담임용) DOM 매핑 → 입력·저장
├── docs/                # SECURITY.md, BOTS.md, 이슈 초안
├── .github/             # PULL_REQUEST_TEMPLATE.md
└── tests/               # 비식별 픽스처 HTML·가명 학급 데이터
```

나이스 **쓰기용 공개 API는 없습니다.** 급식·시간표 등 Open API는 조회용입니다.  
따라서 나이스 반영은 브라우저 탭 간 로컬 자동화만 사용합니다.

## 4. MVP 범위 (1차)

### 웹앱
- [ ] 학급 1개 명단 등록 (엑셀 템플릿 제공)
- [ ] 날짜별 출결: 출석(기본) / 결석(질병·미인정·기타) / 지각 / 조퇴 / 결과 / 출석인정
- [ ] 교시 미지정 시 기본 규칙
  - 지각: 1교시 포함 이전 교시
  - 조퇴: 1교시 포함 이후 교시
  - 결과: 1교시만
- [ ] 사유 필수 검증 (기타결석 등)
- [ ] 여러 날짜 일괄 작성
- [ ] “나이스 전송 대기” 목록과 미리보기

### 매크로/확장
- [ ] 나이스 `일일출결관리(담임용)` 화면 감지
- [ ] 조회 클릭 이후 날짜 이동
- [ ] 학생 매칭 (번호+이름, 실패 시 중단하고 보고)
- [ ] 출결유형·교시 셀·사유 입력 후 저장
- [ ] 성공 시 웹앱 쪽 “반영됨” 표시
- [ ] 주말·공휴일·저장 실패 시 즉시 중단

### 명시적 비범위 (1차에서 하지 않음)
- 생기부 세특·행발 자동입력
- 나이스 서버 직접 호출 / 인증서 우회
- 학생·학부모 계정 연동
- 클라우드에 실명 출결 저장

## 5. 이후 단계 (2차 이후)

- 월별 마감 점검 체크리스트
- 출결 특기사항(장기결석·기타결석) 초안 보조 (자동 확정 금지)
- 전입·편입 학생 예외 플래그
- 학부모 온라인 결석신고와 대조하는 수동 체크 UI
- 오프라인 PWA, 암호화 로컬 백업
- 나이스 화면 개편 시 DOM 셀렉터 핫픽스 채널

## 6. 보안·개인정보

출결 데이터는 학생 개인정보이며 학교생활기록의 일부입니다. 자세한 기준은 `docs/SECURITY.md`입니다. PR은 `.github/PULL_REQUEST_TEMPLATE.md` 체크리스트를 채운 뒤, 보안 관리자 승인 없이 `main`에 넣지 않습니다.

- **로컬 우선**: 이름·번호·출결·사유를 우리 서버·분석 SDK·상용 AI에 보내지 않음. 클라우드 동기화 기본 꺼짐
- **가짜 로그인 금지**: 브라우저 `if`/프론트에 심은 비밀번호로 신원을 가리지 않음. 1차 MVP는 계정 시스템 자체를 만들지 않음
- **IndexedDB는 금고가 아님**: XSS·같은 PC 접근에 노출될 수 있음. 출력은 글자(이스케이프)로만
- **확장 권한 최소**: Manifest V3, 나이스 호스트 + 웹앱 origin만. `<all_urls>` 금지
- **미리보기 없는 나이스 저장 금지**. 부분 실패를 성공으로 표시하지 않음
- **비밀키·service_role·AI 키는 프론트/확장 번들에 없음**
- **GitHub·CI·커밋에는 가명만** (`학생01`). 실명·학교명 원본 캡처를 저장소에 올리지 않음

현장 화면을 보고 시운전하는 절차는 아래 6.1과 `docs/SECURITY.md` 15절을 따릅니다.

### 6.1 실제 나이스 화면 검토·시운전

확장이 동작하려면 **교사가 연 실제 일일출결관리(담임용) 화면**을 보고 DOM·버튼 순서·저장 반응을 확인해야 합니다. 이것은 보안 원칙과 모순되지 않습니다. **실데이터는 저장소에 남기지 않고, 구조만 남깁니다.**

허용:

- 소유 교사가 로그인한 화면을 개발 대화에서 보여 주고, 검토·셀렉터 확인·시운전을 함께 진행
- 이름·번호·사유를 가리거나 자른 이미지, 또는 구조만 적은 메모
- 교사 입회 아래 미리보기 → (합의된 경우에만) 저장. 저장 후 나이스 화면을 육안으로 재확인

금지:

- 인증서, 비밀번호, SSO 화면, 주민번호를 대화·이슈·커밋에 첨부
- 실명 명단·원본 캡처를 GitHub 이슈/PR/`tests/`에 커밋
- 봇이 나이스 로그인을 대신하거나, 미리보기 없이 저장
- CI가 실나이스 계정으로 테스트

저장소에 올리는 산출:

- 가명 학생만 있는 픽스처 HTML (`학생01`)
- 역할·라벨 기준 셀렉터 (`button:저장`, 교시 헤더 등). 실명 CSS 경로에 의존하지 않기
- “이 빌드를 교사 PC에서 시운전함. 저장 여부: 예/아니오” 같은 비식별 기록

시운전 순서:

1. 웹앱 대기열 미리보기 확인
2. 나이스는 교사가 직접 로그인·조회
3. 확장은 사용자 제스처(버튼) 후에만 입력
4. 첫 시운전은 저장 전 중단하거나, 이미 같은 내용이 있는 날짜·소수 행만
5. 나이스에 반영된 값을 교사가 확인한 뒤에만 “반영됨”
6. 오입력은 앱이 롤백하지 않음. 나이스에서 교사가 정정

## 7. 개발 운영 방식 (봇 + GitHub)

한 채널에서 역할 봇이 협업하고, **실제 코드와 결정은 GitHub에 남깁니다.**

```
기능 제안
  → 담당 봇이 이슈 초안 작성
  → 총괄이 우선순위·범위 확정
  → 개발/디자인/매크로가 구현 브랜치에서 작업
  → 현장검증이 수용기준 확인
  → 보안 관리자가 체크리스트 검토 후 Approve
  → main 병합
```

- 브랜치: `feat/이슈번호-짧은이름`, `fix/`, `sec/`
- 커밋: Conventional Commits (`feat:`, `fix:`, `docs:`, `sec:`)
- 이슈 라벨: `web` `ui` `macro` `security` `docs` `needs-teacher-review`
- `main` 보호: 보안 관리자 리뷰 필수

역할 정의는 저장소 `docs/BOTS.md` 및 그록 봇 프로필을 기준으로 합니다.

## 8. 기술 제안 (변경 가능)

| 구분 | 제안 | 이유 |
| --- | --- | --- |
| 웹앱 | Vite + React(또는 Svelte) + TypeScript | 빠른 UI, 타입으로 출결 상태 실수 감소 |
| 상태 | 로컬 IndexedDB (Dexie 등) | 서버 없이 학급 데이터 유지 |
| 양식 | ExcelJS / SheetJS | 교사 엑셀 출석부와 왕복 |
| 확장 | Chrome Manifest V3 | 나이스 탭 DOM 조작 |
| 테스트 | Playwright 비식별 픽스처 + 교사 입회 시운전 | CI는 실계정 없이. 나이스 실화면은 교사 로그인·미리보기 후 육안 확인 |
| 문서 | Markdown + 이슈/PR 템플릿 | 교사도 읽기 쉬운 운영 |

스택은 총괄+개발자가 1주차에 확정합니다.

## 9. 면책

- 나이스 UI·업무 규칙은 시도교육청·학년도·패치에 따라 바뀝니다.
- 자동입력이 실패한 채 부분 저장되거나, 규정이 다른 학생(전입 등)에게 잘못 적용될 수 있습니다.
- 사용 전후로 나이스 화면을 반드시 육안 확인하세요.
- 학교·교육청 보안 지침과 충돌하면 사용을 중단하세요.

## 시작하기

1. 이 저장소를 클론합니다.
2. `docs/issue-template.md` 로 첫 이슈를 등록합니다. 추천 이슈:
   - 학급 명단 CSV 스키마 확정
   - 출결 상태 머신(유형·교시·사유) 정의
   - 나이스 담임용 화면 DOM 조사 (현장 화면은 비식별화한 뒤 픽스처로 저장)
3. 보안 체크리스트를 이슈·PR에 첨부한 뒤에만 구현을 시작합니다.
4. 매크로 시운전은 6.1 절차로 합니다. 인증서·비밀번호는 저장소와 채팅에 올리지 않습니다.
