# 구글 계정 — 신원, 출결은 계정 DB

교사는 구글로 누구인지 증명한다.  
출결 초안(명단·예외·사유)은 **그 교사 계정 행만** 우리 DB에 둔다.  
캐시를 지워도, 컴퓨터를 바꿔도, 같은 구글로 로그인하면 그 학급이 보여야 한다.

브라우저 IndexedDB만 쓰면 사이트 데이터 삭제·기기 변경에 초안이 사라진다. 그건 출결 도구로 이상하다. 1차부터 계정 DB를 쓴다.

## 왜 DB인가

- 출결은 그날 적고 며칠 뒤에도 봐야 한다
- 학교 PC와 집 PC를 오간다
- 크롬 캐시/사이트 데이터 정리는 교사들이 자주 한다

## 1차가 하는 일

1. 구글 로그인 (Google Identity Services). 범위는 `openid email profile`만
2. 서버가 ID 토큰을 검증한 뒤 `sub` → `owner_id`로 세션을 연다
3. 명단·출결 초안은 Postgres(Supabase)에 저장한다. 행마다 `owner_id`
4. RLS: `owner_id = auth.uid()` 인 행만 SELECT/INSERT/UPDATE/DELETE
5. 로그인 전에 출결을 쓰지 않는다. 게스트 없음
6. 화면 상단에 항상 보이게: **「출결 초안은 계정에 저장됩니다. 이 컴퓨터 캐시를 지워도 남고, 같은 구글이면 다른 PC에서도 보입니다.」**

Drive, Gmail, Contacts, 캘린더 권한은 받지 않는다.

## 1차가 하지 않는 일

- 프론트에서 비밀번호를 비교하거나 `localStorage.isAdmin`으로 권한 판단
- Client Secret, `service_role`, Firebase Admin 키를 프론트·확장에 넣기
- 스토리지 버킷 public
- 다른 교사 `owner_id` 행을 URL id만 바꿔 읽기 (IDOR → 거부)
- 출결 원문을 GitHub·이슈·Analytics에 보내기
- 나이스 인증서·비밀번호를 DB에 저장

## 화면 안내 (필수, 숨기지 않음)

로그인 카드, 히트맵 홈, 미리보기, 사용 방법에 같은 뜻을 큰 글으로 둔다. 문구 원문은 `docs/privacy.md`.

> 출결 초안은 출결메이트 계정 DB에 저장됩니다.  
> 브라우저 캐시·방문 기록을 지워도 지워지지 않습니다.  
> 다른 컴퓨터에서 같은 구글 계정으로 로그인하면 이어서 볼 수 있습니다.  
> 나이스에 이미 저장한 출결은 나이스에 있습니다. 이 DB는 초안입니다.  
> 「계정 초안 삭제」를 누르면 이 계정 초안이 DB에서 삭제됩니다.

## 토큰

- ID 토큰은 서버(또는 Supabase Auth)가 검증하기 전 신원으로 쓰지 않는다
- `service_role`은 서버 전용. 브라우저 금지
- Access token을 소스에 심지 않는다
- 로그에 이메일·`sub` 전체·학생 이름을 남기지 않는다

## 데이터 모양

```json
{
  "owner_id": "auth-uid",
  "date": "2026-09-03",
  "number": 1,
  "name": "학생01",
  "category": "illness",
  "type": "late",
  "period": 3,
  "reason": "",
  "status": "queued"
}
```

클라이언트에서 필터만 하고 끝나면 부족하다. RLS가 같은 조건을 강제한다.

## 개인정보

학생 이름·출결 사유는 개인정보다. 이 DB를 쓰는 순간 학교(또는 운영 교사)가 처리 목적을 안내해야 한다.  
시안 목업 가명은 괜찮다. GitHub 픽스처는 `학생01`을 쓴다.

## 비용

행 텍스트만 두면 Supabase 무료 한도로 담임 수 학급은 보통 충분하다.  
공개 버킷·무제한 API 키·프론트 service_role이 요금 폭탄이다. 그건 금지.
