# 출결 데이터 계약

나이스 **일일출결관리(담임용)** 화면(2026-08-30 현장 캡처)과 웹앱·확장 대기열을 맞추는 문서다.  
실명·학교 식별 정보는 이 문서에 적지 않는다. 픽스처는 `학생01`만 쓴다.

## 화면이 알려 준 것

- 주소 형태: `*.neis.go.kr` (예: 서울 `sen.neis.go.kr`). 확장은 특정 교육청만 하드코딩하지 않는다.
- 메뉴: `[학급담임] - [출결관리] - [일일출결관리(담임용)]`
- 위쪽 단계: 교과시간별출결등록 → **일일출결관리(담임용)** → 반별일출결마감관리 → 반별월출결마감관리 → 월출결마감현황 → 출결특기사항등록
- 조회 조건: 학년도, 학년, 반, 일자 후 **조회**
- 그리드 열: `번호 | 성명 | 마감 | 조회 | 1교시(과목) … n교시(과목) | 종례 | 사유`
- 교시 칸은 과목명이 헤더에 붙고, 미처리 시 `미마감`으로 표시된다.
- 조회·종례는 교시와 **다른 열**이다. 비어 있는 입력칸이다.
- 일괄 줄: 체크 + 출석 등 드롭다운 + 사유. 선택 행에 한꺼번에 적용하는 용도로 보인다.
- 오른쪽 버튼: 동아리활동, 자유학기활동, **저장**, 출결마감, 마감취소, 출력
- **저장을 누르지 않고 날짜·학급을 바꾸면 입력값이 사라진다.** 날짜를 떠나기 전에 저장이 필수다.
- 출결마감 버튼은 1차 자동화 대상이 아니다.
- 출석번호는 연속이 아닐 수 있다. 번호+성명이 다르면 중단한다.
- 1차 범위는 이 화면의 입력·**저장**까지. 반별/월 마감·특기사항은 이후 단계.

팝업 제목은 **출결마감구분**이다. 라벨은 아래와 같다.

## 나이스 팝업 라벨 (그대로 사용)

이전 문서의 “내용/인정”은 폐기한다. 화면 문구를 따른다.

### 구분 (`category`)

| 코드 | 화면 |
| --- | --- |
| `illness` | 질병 |
| `unexcused` | 미인정 |
| `other` | 기타 |
| `recognized` | 출석인정 |

### 종류 (`type`)

| 코드 | 화면 |
| --- | --- |
| `late` | 지각 |
| `early_leave` | 조퇴 |
| `absence` | 결석 |
| `result` | 결과 |

적용 전에 구분·종류를 각각 하나 고른다. 사유는 텍스트.

기타이면 사유 필수. 그 외는 칸이 있으면 그대로 전달.

## 기본값

기록이 없으면 **출석**이다. 출석 행은 전송하지 않는다.

## 칸이 채워지는 규칙 (현장 예시로 확정)

구분·종류를 고른 다음 **교시 칸 P를 한 번 클릭**하면, 나이스가 종류에 따라 `/`를 여러 칸에 넣는다.  
확장도 `/`를 칸마다 입력하지 않고 **같은 칸을 한 번 클릭**한다.

예시: 구분=질병, **3교시 칸 클릭**.  
마감 열에는 `구분+종류`가 붙는다. 예: `질병지각`.  
화면 열 이름은 **조회**다. 조례라고 부르는 그 칸이다.  
적용되지 않은 교시 칸은 `미마감`으로 남는다.

하루 열 순서: `조회 | 1 … n교시 | 종례`

| 종류 | 마감 열 | `/` 가 들어가는 칸 |
| --- | --- | --- |
| 지각 | `{구분}지각` | 조회 + 1교시부터 **P 포함 이전** |
| 조퇴 | `{구분}조퇴` | **P 포함 이후** 교시 + 종례 |
| 결석 | `{구분}결석` | 조회 + **모든** 교시 + 종례 |
| 결과 | `{구분}결과` | **P만** |

3교시·6교시 날 질병 예시:

| 종류 | 조회 | 1 | 2 | 3 | 4 | 5 | 6 | 종례 | 마감 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 지각 | `/` | `/` | `/` | `/` | 미마감 | 미마감 | 미마감 | (빈칸) | 질병지각 |
| 조퇴 | (빈칸) | 미마감 | 미마감 | `/` | `/` | `/` | `/` | `/` | 질병조퇴 |
| 결석 | `/` | `/` | `/` | `/` | `/` | `/` | `/` | `/` | 질병결석 |
| 결과 | (빈칸) | 미마감 | 미마감 | `/` | 미마감 | 미마감 | 미마감 | (빈칸) | 질병결과 |

웹앱은 구분·종류·기준 교시 P만 저장한다.  
확장은 그 행의 P 칸을 클릭하고, 위 표대로 `/`와 마감 라벨이 생겼는지 확인한다. 칸마다 `/`를 타이핑하지 않는다.

아직 확인하지 않은 것: 기준 교시가 1교시·마지막 교시일 때, 구분만 다를 때 라벨 문자열, 사유가 행 끝 칸으로 복사되는지.

## 대상 칸 코드 (`slots`)

| 코드 | 화면 열 |
| --- | --- |
| `close` | 마감 (라벨 문자열) |
| `morning` | 조회 |
| `period:1` … `period:n` | n교시 |
| `afternoon` | 종례 |
| `reason` | 행 끝 사유 |

교시 수는 날마다 다를 수 있다. 헤더를 읽고 n을 정한다.

## 저장

입력 후 **반드시 저장**한다.  
저장하지 않은 채 일자·학년·반을 바꾸거나 조회를 다시 누르면 그날 작업이 사라진다.  
확장은 한 날짜 작업을 끝낸 뒤 저장을 누르고, 그리드 값이 남아 있는지 확인하기 전에는 다음 날짜로 넘어가지 않는다.  
출결마감은 누르지 않는다.

## 명단 CSV

```text
grade,class,number,name
2,3,1,학생01
2,3,2,학생02
```

실명 CSV는 저장소에 올리지 않는다.

## 대기열 JSON

```json
{
  "date": "2026-08-28",
  "year": 2026,
  "grade": 2,
  "class": 3,
  "number": 1,
  "name": "학생01",
  "category": "illness",
  "type": "late",
  "period": 3,
  "reason": "",
  "status": "queued"
}
```

| 필드 | 설명 |
| --- | --- |
| `date` | `YYYY-MM-DD` |
| `year` `grade` `class` | 조회 조건. 화면 드롭다운과 같아야 한다 |
| `number` | 출석번호. 1차 매칭 |
| `name` | 성명. 번호와 불일치면 중단 |
| `category` | 팝업 **구분** |
| `type` | 팝업 **종류** |
| `period` | 클릭할 교시 번호 P. `/` 범위는 종류로 계산 |
| `reason` | 팝업 사유 및/또는 행 사유 |
| `status` | `draft` · `queued` · `synced` · `error` |

웹앱과 확장이 이 키를 공유한다. 이름을 바꾸려면 이 문서를 먼저 고친다.

## 확장 동작 초안

1. `*.neis.go.kr` 에서 일일출결관리(담임용) 화면인지 확인
2. 학년도·학년·반·일자가 대기열과 같은지 확인. 다르면 중단
3. 조회가 끝나 그리드가 떠 있는지 확인
4. 번호+성명으로 행을 찾는다. 없으면 중단
5. 출결마감구분에서 구분·종류·사유를 넣거나, 일괄 줄에서 고른다
6. 그 행의 **P교시 칸을 한 번 클릭**한다. `/`는 나이스가 퍼뜨린다
7. 마감 열과 `/` 범위가 표와 같은지 확인한다
8. 그날 대기열이 끝나면 **저장**. 값이 남았는지 보기 전에 날짜를 바꾸지 않는다
9. 출결마감은 누르지 않는다. 육안 확인 뒤에만 `synced`

## 상태

| status | 의미 |
| --- | --- |
| `draft` | 웹앱에만 있음 |
| `queued` | 미리보기 후 전송 대기 |
| `synced` | 저장 후 교사 육안 확인 |
| `error` | 매칭 실패·조건 불일치·사유 공란·저장 실패 |

## 화이트리스트

`category`·`type`·`status` 외 값, 1 미만 `period`는 버린다.
